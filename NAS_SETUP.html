00

Wo wir gerade stehen

Der lokale Hardwaretest ist gelungen.

Bestätigt am 23. September: Der ESP32 wurde als /dev/ttyACM0 erkannt, nahm PLAY HI an und spielte hörbar über den angeschlossenen Verstärker. Auch der lokale Webseiten-API-Aufruf für HI funktionierte. Beim erneuten Einstecken erschien keine neue USB-Überstrommeldung.

Live-Status vom 24. September: Die normale Firmware wifi_message verbindet sich mit dem nahen FRITZ!Repeater, nachdem die ESP-Sendeleistung auf 8,5 dBm begrenzt wurde. Drei Firmware-Neustarts erreichten eine IP-Adresse, starteten I²S und bestätigten NAS-Polling mit geprüftem HTTPS und Gerätetoken. Beim Gegenvergleich mit normaler Sendeleistung scheiterte die Verbindung erneut. Der Repeater nutzt WPA2 und 2,4 GHz/Wi-Fi 4; neue Geräte sind erlaubt. Die genaue elektrische oder Funk-Ursache ist noch offen. Größere Entfernung und Dauerbetrieb am Ausstellungsort müssen noch geprüft werden. Ein Live-Modellaufruf lieferte „I AM HERE“. Nach Umstellung der WLAN-Wiedergabe auf dieselbe kontinuierlich gepufferte Audioroutine wie beim USB-Test wurde die Nachricht einmal über die öffentliche API ausgelöst und vom Nutzer hörbar bestätigt. Die Handy-Decodierung mit dieser Firmware muss noch geprüft werden. GitHub Pages, Funnel, NAS-API und GPT-6 Luna wurden zuvor erfolgreich getestet.

Du musst die funktionierende Verkabelung für diese Anleitung nicht wieder zerlegen. In älteren PC-Logs gab es allerdings Überstrommeldungen. Falls so eine Meldung erneut erscheint, USB abziehen und die Stromversorgung prüfen, bevor du weiter testest. Der kurze Test zeigt noch keinen ganzen Tag Dauerbetrieb.

01

Die passende Webseite veröffentlichen

GitHub Pages ist schon eingerichtet.

Öffentliche Adresse

https://jr-4b3.github.io/ALIVE/ · Quelle: Branch main, Ordner /docs.

Die gebauten Dateien in docs/ gehören zur Veröffentlichung. Für Besucher genügt der druckbare QR-Code: Er öffnet die Webseite mit vorausgefüllter NAS-Adresse. Verbindungseinstellungen liegen unter einem ausklappbaren Bereich.

Geheimnisse bleiben privat: .env, secrets.h, der OpenAI-Schlüssel und beide Zugangstokens gehören nicht nach GitHub. Der öffentliche Ausstellungsmodus erlaubt nur kurze Nachrichten und Wiedergabe ohne Besucher-Login. Für Modellanfragen gelten 10 Sekunden Abstand und maximal 300 Anfragen pro laufenden 24 Stunden.

02

DS720+ vorbereiten

Der NAS führt die Python-API dauerhaft als Container aus.

  1. Installiere in DSM unter Paket-Zentrum den Container Manager und Tailscale. Melde den NAS bei Tailscale an. Für Funnel ist mindestens Version 1.38.3 erforderlich.
  2. Aktiviere für die Einrichtung Systemsteuerung → Terminal & SNMP → SSH. Dein NAS ist im aktuellen Heimnetz unter 192.168.178.28 bzw. DS720.local erreichbar; SSH-Port 22 ist offen. Verbinde dich mit ssh DEIN_DSM_BENUTZER@192.168.178.28. Ersetze den Benutzernamen durch deinen DSM-Login. Für sudo brauchst du Administratorrechte. Die IP kann sich durch DHCP später ändern.
  3. Erstelle im File Station /volume1/docker/alive und kopiere die gleiche veröffentlichte Version des Projekts dorthin. Benötigt werden unter anderem Dockerfile.nas, compose.nas.yml, nas.env.example, die Python-Dateien und docs/. Ein entpacktes ZIP des GitHub-Stands genügt. Passe volume1 an, falls dein Volume anders heißt.
  4. Erzeuge auf dem NAS die private Konfiguration mit zwei verschiedenen Zufallstokens. Das Skript lässt eine vorhandene .env unangetastet:
    NAS · SSH 
    cd /volume1/docker/alive
sh nas-bootstrap.sh
  5. Bearbeite .env auf dem NAS: Die beiden Tokens hat das Skript schon gesetzt; trage deinen gültigen OPENAI_API_KEY und ALIVE_PUBLIC_DEMO=1 ein. ALIVE_WEB_ORIGIN bleibt https://jr-4b3.github.io — ohne /ALIVE/. Schütze die Datei mit chmod 600 .env.
  6. Baue und starte den Container. Der letzte Befehl muss HTML von ALIVE ausgeben:
    NAS · SSH 
    cd /volume1/docker/alive
sudo /usr/local/bin/docker compose --env-file .env -f compose.nas.yml up -d --build
sudo /usr/local/bin/docker compose --env-file .env -f compose.nas.yml ps
sudo /usr/local/bin/docker compose --env-file .env -f compose.nas.yml logs --tail=50
curl -i http://127.0.0.1:8765/

Der Container bindet Port 8765 nur an die lokale Adresse des NAS. restart: unless-stopped startet ihn nach einem Reboot erneut; ein Docker-Volume erhält den vorbereiteten Antwortzustand. Im Container Manager → Projekt siehst du den Dienst. Falls docker compose fehlt, prüfe zuerst die Installation bzw. Version des Container Managers.

03

Öffentliche HTTPS-Adresse einrichten

Tailscale Funnel macht nur die ALIVE-API erreichbar.

NAS · SSH 
sudo /var/packages/Tailscale/target/bin/tailscale version
sudo /var/packages/Tailscale/target/bin/tailscale status
sudo /var/packages/Tailscale/target/bin/tailscale funnel --bg 8765
sudo /var/packages/Tailscale/target/bin/tailscale funnel status

Beim ersten Start kann Tailscale einen Link zur Freigabe von Funnel, MagicDNS, HTTPS-Zertifikaten oder einer Richtlinie anzeigen. Öffne ihn, bestätige die Einrichtung und führe den Befehl erneut aus. Notiere die öffentliche https://...ts.net-Adresse. Durch --bg bleibt Funnel nach Neustarts aktiv. Besucher brauchen selbst kein Tailscale.

Gegenprobe: Schalte das WLAN am Handy aus und öffne die Funnel-Adresse über Mobilfunk. Die ALIVE-Seite der API sollte über HTTPS laden. tailscale serve wäre nur innerhalb deines privaten Tailnets erreichbar; für Besucher brauchst du funnel.

Gib dafür nicht den DSM-Administrationsport öffentlich frei. Falls Funnel nicht startet, prüfe zuerst die Tailscale-Version und den Funnel-Status.

04

ESP32 auf WLAN umstellen

Einmal flashen, danach reicht ein USB-Netzteil.

Die aktuelle Lautsprecherverkabelung hat beim Test funktioniert. Prüfe vor dem Flashen, dass die USB-Verbindung stabil ist. Wenn du irgendeine Leitung ändern musst, trenne vorher die Stromversorgung.

Kopiere im lokalen Projekt firmware/esp32_i2s_emitter/include/secrets.example.h nach secrets.h im selben Ordner. Trage dort Folgendes ein:

FeldWert
ALIVE_WIFI_SSID
ALIVE_WIFI_PASSWORD		WLAN oder eigener Hotspot für den ESP32
ALIVE_SERVER_URLÖffentliche Funnel-Adresse https://...ts.net, ohne Schrägstrich am Ende
ALIVE_DEVICE_TOKENGeräte-Token aus der NAS-Datei .env
ALIVE_SERVER_CA_CERTVertrauenswürdiges Root-CA-Zertifikat der Funnel-Zertifikatskette als PEM

Verwende ein passwortgeschütztes 2,4-GHz-WLAN ohne Browser-Login. Ein eigener Hotspot oder Reiserouter ist oft einfacher als Veranstaltungs-WLAN. Für die HTTPS-Zertifikatsprüfung braucht der ESP32 auch die korrekte Internetzeit. Ohne ALIVE_SERVER_CA_CERT nutzt die aktuelle Firmware eine unsichere TLS-Testeinstellung; ergänze das passende CA-Zertifikat vor dem Ausstellungsbetrieb.

Lokaler PC · Projektordner 
.tmp/platformio-venv/bin/platformio run --project-dir firmware/esp32_i2s_emitter -e wifi_message -t upload --upload-port /dev/ttyACM0

Ersetze /dev/ttyACM0, falls der ESP32 dann einen anderen Port hat. Nach dem Flashen fragt er die NAS-API mit dem Geräte-Token ab. Alte Play-Befehle werden beim Neustart nicht nachträglich abgespielt. Am Ausstellungsort reicht ein geeignetes USB-Netzteil. Der Lautsprecher gehört nur zwischen SPK+ und SPK−, nicht an GND.

06

Für den Ausstellungsbetrieb

Kurzcheck nach Neustart und bei Updates.

NAS · SSH 
cd /volume1/docker/alive
sudo /usr/local/bin/docker compose --env-file .env -f compose.nas.yml ps
sudo /var/packages/Tailscale/target/bin/tailscale funnel status

Nach einem Code-Update kopiere den passenden veröffentlichten Projektstand auf den NAS und starte den Container mit sudo /usr/local/bin/docker compose --env-file .env -f compose.nas.yml up -d --build neu. Behalte .env und das Docker-Volume. GitHub Pages und NAS sind zwei getrennte Veröffentlichungen; ihre API-Versionen müssen zusammenpassen.
